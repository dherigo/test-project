# 개발 계획 — 현장별 공정·기성 대시보드

## 한눈에 보기

- EPIC(큰 작업 묶음) 3개, Story(작은 작업) 13개입니다. 실습조건의 상한(EPIC 3개 이하, Story 15개 미만)에 맞췄습니다.
- 순서: ① 자료 가져오기·필터·현황·추이 → ② 점검 현장·기록 펼침·CSV → ③ 근거를 보여주는 AI 질의.
- EPIC은 하나씩만 만듭니다. 끝날 때마다 자동 검사를 돌리고, 브라우저에서 확인할 행동과 결과를 하나씩 알려 드립니다.
- 학습자가 "확인했다"고 답하기 전에는 완료로 표시하지 않습니다.
- 마지막 Story(S13)가 끝나면 결과와 남은 작업을 보고하고 멈춥니다. GitHub 저장과 Vercel 배포는 이 계획에 넣지 않고, 각각 사용자가 따로 요청한 뒤에만 진행합니다.

> 모든 현장·금액·기록은 교육용 가상 자료입니다. 숫자는 `data/검산표.md`의 값과 같아야 합니다.

### EPIC 2 — 점검 현장·기록 펼침·CSV

| 번호 | 사용자가 할 수 있는 일 | 확인할 행동 (브라우저) | 보여야 할 결과 |
|---|---|---|---|
| S6 | 12개 현장을 한 표로 비교합니다. | 현장별 비교표를 엽니다(2026-09 전체). | 12행이 공정차이 작은 순으로 나오고 맨 위가 D(점검)입니다. 표 위에 "정상 6 · 주의 3 · 점검 3", 열에 지역·유형·당월 주요 공종·금액·공정·상태, 맨 아래 합계 행 630,700 / 424,063.4 / 67.2% / 73.2%가 보입니다. 2025-10으로 바꾸면 당월기성액 칸이 "계산 불가"입니다. |
| S7 | 현장의 상황·대응 기록을 펼칩니다. | 비교표에서 D의 "펼치기"를 누릅니다. 다시 누릅니다. | 같은 페이지 안에서 D 행 아래에 공사기간(2024-09-02 ~ 2027-02-28), 기록된 상황, 기록된 대응 계획이 열리고, 다시 누르면 닫힙니다. 별도 페이지로 이동하지 않습니다. |
| S8 | 점검 현장 순위를 보고 비교표로 이동합니다. | 현황 요약의 점검 줄을 봅니다. D 줄을 누릅니다. 현황 요약으로 돌아가 월을 2025-10으로 바꿉니다. | 점검 줄: D(-10.7pp) → I(-7.6pp) → K(-5.4pp), 각 줄에 계획·실제 공정률·공정차이·기성률(D: 86.5% / 75.8% / -10.7pp / 69.4%). D를 누르면 비교표로 이동해 D 행이 강조되고 기록이 펼쳐집니다. 2025-10은 "점검 대상 없음"이 보입니다. |

### EPIC 3 — 근거를 보여주는 AI 질의

| 번호 | 사용자가 할 수 있는 일 | 확인할 행동 (브라우저) | 보여야 할 결과 |
|---|---|---|---|
| S10 | AI 화면에서 지금 범위와 예시 질문을 봅니다. | AI에게 묻기를 엽니다. 월이나 현장 필터를 바꿉니다. | 위쪽에 기준 월·지역·유형·현장이 표시되고, 예시 질문 3개("D가 늦어진 원인과 대응은?"·"점검 현장은 어디인가요?"·"J의 7월 기성은 왜 늘지 않았나요?")가 보입니다. 필터를 바꾸면 이전 답변이 지워집니다. |
| S11 | AI에게 질문하고 근거가 붙은 답을 받습니다. | 2026-09에서 현장 D를 고르고 "D가 늦어진 원인과 대응은?"을 묻습니다. 전체로 바꿔 "점검 현장은?"을 묻습니다. "실제 준공일·미수금은?"을 묻습니다. | D: 공급 정상화 후에도 남은 지연과 주간 확인 계획을 기록대로 설명하고 69.4%를 인용합니다. 점검: D → I → K. 준공일·미수금: "자료 없음"이고 계약상 준공일과 실제 완료일을 구분합니다. 답변에 기준 월·현장·근거 숫자·참고한 기록 필드가 붙고, 기록은 "기록된 상황"·"계획된 대응"으로 쓰입니다. |
| S12 | AI가 안 될 때도 대시보드와 CSV를 씁니다. | 키를 비운 상태로 질문을 보냅니다. 답변을 기다리는 동안 월을 바꿉니다. 현황 요약과 CSV 내보내기를 다시 사용합니다. | "답변 기다리는 중"에 이어 "AI 연결 실패"와 이유 한 줄, "대시보드와 CSV는 계속 사용할 수 있습니다"가 보입니다. 현황·비교표·CSV는 정상 동작합니다. 기다리는 중에 범위를 바꾸면 이전 질문의 응답이 새 범위에 나타나지 않습니다. |
| S13 | 로컬 전체 검증 결과를 확인합니다. | 정답 숫자 표(PRD 8장)의 14개 항목을 화면에서 차례로 확인합니다. | 자동 검사 통과 결과와 `docs/05_테스트결과.md`(확인한 것과 미확인을 구분)가 있습니다. 확인하지 못한 것은 "미확인"으로 적습니다. 학습자가 확인했다고 답한 뒤에 완료로 표시하고 멈춥니다. |

## 3. 진행 규칙

| 규칙 | 내용 |
|---|---|
| EPIC 단위 | EPIC 하나를 만들고, 자동 검사를 돌리고, 브라우저 확인을 받은 뒤 다음 EPIC으로 갑니다. 여러 EPIC을 한 번에 만들지 않습니다. |
| 완료 표시 | 학습자가 확인했다고 답하기 전에는 완료로 표시하지 않습니다. 화면만 있고 동작하지 않는 상태는 완료가 아닙니다. |
| 확인 방법 | 각 Story의 "확인할 행동"은 브라우저에서 바로 보고 판단할 수 있게 적었습니다. 터미널·코드·개발자 도구를 보게 하지 않습니다. |
| AI 확인 | S11·S12는 Gemini 키가 있어야 실제 AI로 확인됩니다. 키가 없으면 "모의 응답"으로 표시해 확인하고, `05_테스트결과.md`에 "실제 AI 미확인"으로 적습니다. |
| 같은 오류 | 같은 오류가 세 번 반복되면 같은 방법을 다시 쓰지 않고 다른 방법을 제안합니다. |

## 4. 이 계획 밖의 단계 — 사용자가 따로 요청한 뒤에만 진행

아래는 Story도, EPIC의 완료 조건도 아닙니다. S13이 끝나면 결과와 남은 작업을 보고하고 멈춥니다.

| 단계 | 시작 조건 | 하지 않는 것 |
|---|---|---|
| GitHub 저장 | 사용자가 저장소 주소를 알려 주고 "이 저장소에 올려 줘"처럼 명시적으로 요청할 때만 그 범위에서 진행합니다. 끝나면 보고하고 멈춥니다. | 저장소 생성·커밋·푸시를 요청 전에 실행하지 않습니다. 저장 요청에는 배포가 포함되지 않습니다. |
| Vercel 배포 | GitHub 저장과 별개로, 배포할 프로젝트·저장소를 정해 사용자가 따로 요청할 때만 진행합니다. STEP 11에서 사용자가 직접 진행하는 단계입니다. | 프로젝트 생성·저장소 연결·환경 변수 등록·미리보기 또는 운영 배포·자동 배포 설정을 요청 전에 하지 않습니다. |

"구현 완료"·"확인했어요"·"다음으로"·"알아서 해 주세요"만으로는 저장·배포를 시작하지 않습니다.
