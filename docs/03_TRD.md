# TRD — 현장별 공정·기성 대시보드

## 한눈에 보기

- Next.js(화면과 서버를 한 프로젝트로 만드는 도구) + TypeScript로 만들고, 계산이 맞는지는 Vitest(자동 검사 도구)로 확인합니다.
- 자료 읽기·검사·계산·CSV 만들기는 모두 브라우저에서 합니다. 서버에 저장하거나 데이터베이스를 쓰지 않습니다.
- 서버는 AI 질문 하나만 맡습니다. Gemini API(`gemini-3.8-flash`)를 서버에서만 부르고, 키는 `.env.local`에만 둡니다.
- 계산 코드는 한 곳(`lib/`)에 모아 화면·CSV·AI가 같은 함수를 씁니다. 그래서 세 곳의 숫자가 어긋나지 않습니다.
- 월 비용은 0원(무료 구간)입니다. GitHub 저장과 Vercel 배포는 사용자가 따로 요청한 뒤에만 진행합니다.

> 모든 현장·금액·기록은 교육용 가상 자료입니다. 계산 기준은 `data/데이터설명.md`와 `data/검산표.md`입니다.

## 1. 사용하는 기술과 고른 이유

| 구분 | 기술 | 고른 이유 |
|---|---|---|
| 만드는 도구 | Next.js + TypeScript | 실습조건에서 정했습니다. 화면과 AI용 서버 코드를 한 프로젝트에 둘 수 있습니다. TypeScript는 숫자·글자 같은 자료의 종류를 코드에서 미리 확인해 줍니다. |
| 자동 검사 | Vitest | 실습조건에서 정했습니다. 정답 숫자(67.2%, -2.0pp 등)를 코드로 확인합니다. |
| AI | Gemini API, 모델 `gemini-3.8-flash` | 실습조건에서 정했습니다. 서버에서만 호출합니다. |
| 자료 처리 | 브라우저에서 파일 읽기·검사·계산 | 실습조건에서 정했습니다. 서버 저장·데이터베이스가 없어 구조가 단순합니다. |
| 화면 꾸미기 | CSS(Tailwind CSS 사용 예정) (AI 결정) | 시안이 `design/DESIGN.md`의 색·글자 기준으로 정리돼 있어 그대로 옮기기 쉽습니다. 시안 코드 활용 가능 여부는 구현할 때 확인합니다. |
| 차트 | 직접 그리는 SVG(화면에 선·막대를 그리는 웹 표준 방식) (AI 결정) | 선 2개와 막대 12개뿐이라 별도 차트 도구를 설치하지 않아도 됩니다. 설치할 것이 적을수록 문제가 적습니다. |
| CSV 읽기·쓰기 | 직접 만든 작은 코드 (AI 결정) | 따옴표·쉼표·BOM(파일 맨 앞 글자 표시) 처리만 필요합니다. 이 부분은 Vitest로 함께 확인합니다. |
| AI 호출 방식 | 서버에서 `fetch`(인터넷으로 요청 보내는 기본 기능)로 Gemini에 요청 (AI 결정) | Gemini 전용 도구를 설치하지 않아 의존이 줄어듭니다. 요청 주소·형식은 구현 직전에 Gemini 공식 문서로 확인해야 하며, 지금은 확인하지 않았습니다. |

실습조건에 없는 서비스(로그인, 데이터베이스, 외부 저장소)는 쓰지 않습니다. GitHub·Vercel·Gemini 외의 가입도 요구하지 않습니다.

## 2. 구조

| 위치 | 맡는 일 | 관련 기능 |
|---|---|---|
| `app/` 화면 4개 | 현황 요약(첫 화면), 현장별 비교표, 자료 가져오기, AI에게 묻기 | F1~F16 |
| `app/api/ask/` (서버) | AI 질문 요청을 받아 Gemini에 보내고 답을 돌려줌. 이 서버 코드만 키를 읽습니다. | F14, F15 |
| `lib/parse` | CSV·JSON 읽기 (BOM 제거, `month`·`siteId`를 문자로 읽기) | F12 |
| `lib/validate` | 가져오기 검사 규칙(FRD 3장) 전부. 오류에 행 번호·열 이름·이유 포함 | F12 |
| `lib/calc` | 공정차이·상태·기성률·가중평균·당월기성액·추이·점검 순위. 소수 오차를 막기 위해 입력값을 10배 한 정수로 계산 | F1~F11 |
| `lib/filter` | 월·지역·유형·현장 필터와 "현장이 범위에서 빠지면 전체로 되돌리기" | F1~F5 |
| `lib/csv` | 필터 범위 CSV 만들기(원본 15열 + 계산 4열, UTF-8 BOM) | F13 |
| `lib/aiContext` | AI에 보낼 자료 만들기: 원문 기록과 계산된 요약을 나눠 담음 | F14 |
| 앱 상태(브라우저 메모리) | 가져온 144행과 현재 필터를 보관. 새로고침하면 사라짐 | F16 |
| `tests/` | Vitest 검사. 정답 숫자·오류 파일 3종·필터·CSV·AI 자료 구성 | 전체 |

규칙: 숫자를 계산하는 코드는 `lib/calc` 한 곳에만 둡니다. 화면·CSV·AI 자료는 모두 이 함수의 결과를 가져다 씁니다. 원본에 기성률·공정차이·상태를 저장하지 않습니다.

## 3. 자료가 어디서 어디로 가는지

| 순서 | 어디서 | 어디로 | 무엇이 | 서버에 남는가 |
|---|---|---|---|---|
| ① | 사용자 PC의 파일 | 브라우저 | CSV 또는 JSON 파일을 읽음 | 아니요 (서버로 보내지 않음) |
| ② | 브라우저 | 브라우저 | 검사 → 미리보기 → "전체 교체" 승인 시 144행으로 교체 | 아니요 |
| ③ | 브라우저 | 브라우저 | 필터 범위의 숫자·표·추이 계산 | 아니요 |
| ④ | 브라우저 | 사용자 PC | CSV 파일 만들어 내려받기 | 아니요 |
| ⑤ | 브라우저 | 우리 서버 코드(`/api/ask`) | 질문 + 필터 범위 + 선택 월 원문 행(+추이 질문이면 월별 행). 숫자는 서버에서 같은 계산 코드로 다시 계산 (AI 결정) | 아니요 (저장·기록하지 않음) |
| ⑥ | 우리 서버 코드 | Gemini API | 질문 + 원문 기록 + 계산된 요약(구분해서) | Gemini 쪽 처리 규정을 따름 |
| ⑦ | Gemini API | 서버 → 브라우저 | 답변 글자. 화면에 기준 월·현장·근거 숫자·기록 필드와 함께 표시 | 아니요 |

- ⑤에서 서버가 숫자를 다시 계산하는 이유: 브라우저에서 보낸 숫자를 그대로 믿으면 화면과 AI 답변이 어긋날 수 있기 때문입니다.
- 범위가 바뀌면 브라우저가 진행 중인 요청을 취소하고, 늦게 온 응답은 화면에 넣지 않습니다(F15).

## 4. AI 모델과 키 보관 방법

| 항목 | 정한 것 | 근거 |
|---|---|---|
| 모델 | `gemini-3.8-flash` | 실습조건에서 정했습니다. 이 모델 이름이 실제로 쓸 수 있는지는 아직 확인하지 않았고, 키를 넣고 첫 호출할 때 확인합니다. |
| 호출 위치 | 서버(`app/api/ask/`)에서만 | 브라우저 코드에 키가 들어가면 누구나 볼 수 있습니다. |
| 키 이름·위치 | `.env.local`의 `GEMINI_API_KEY` | `NEXT_PUBLIC_`로 시작하는 이름은 브라우저로 노출되므로 쓰지 않습니다. 이름은 (AI 결정)입니다. |
| 키 받는 방법 | 강사가 나눠 준 키를 학습자가 `.env.local`에 직접 입력 | 실습조건 규칙입니다. 대화·화면·코드에는 키 값을 쓰지 않습니다. |
| GitHub | `.gitignore`에 `.env.local` 포함, 키는 절대 올리지 않음 | 실습조건 규칙입니다. 키 이름만 적은 `.env.example`은 만들 수 있습니다. |
| 오류 처리 | 키 없음·한도 초과·시간 초과(20초) (AI 결정)·연결 실패를 구분해 "AI 연결 실패" 이유 한 줄로 안내. 대시보드·CSV는 그대로 동작 | FRD F14 |
| 질문 제한 | 질문 500자 이하, 한 번에 한 질문 (AI 결정) | 비용·오작동을 막기 위한 값입니다. |
| 지시문 | "기록된 상황"·"계획된 대응"으로 말하기, 원인·완료 단정 금지, 자료에 없으면 "알 수 없음", 계약상 준공일은 일정일 뿐 | 실습조건·검산표의 AI 범위 |
| 로그 | 질문·답변·키를 서버 로그에 남기지 않음 | 키·자료 노출 방지 |

## 5. 실행 방법 (내 컴퓨터에서)

| 순서 | 하는 일 | 확인 |
|---|---|---|
| 1 | 프로젝트 폴더(`site-dashboard`)에서 필요한 도구 설치 (`npm install`) | 오류 없이 끝남 |
| 2 | `.env.local` 파일을 만들고 강사가 준 키를 `GEMINI_API_KEY=`에 입력 | 파일이 GitHub 제외 목록에 있음 |
| 3 | 개발 서버 실행 (`npm run dev`) | 브라우저에서 주소가 열림. 기본 포트가 쓰이고 있으면 다른 번호로 실행하고, 이미 실행 중인 다른 프로그램은 끄지 않음 |
| 4 | 자동 검사 실행 (`npm test`) | 정답 숫자 검사가 모두 통과 |
| 5 | 브라우저에서 `data/현장공정기성.csv`를 가져오기 | 144행·2026-09 기성률 67.2% |

사용 환경: Node.js(자바스크립트 실행 프로그램)와 npm이 설치돼 있어야 합니다. 설치 여부와 버전은 구현 시작할 때 확인하며, 지금은 확인하지 않았습니다.

## 6. 배포 방법 (안내만 합니다)

앱 구현과 로컬 검증이 끝나면 결과를 보고하고 멈춥니다. 아래는 사용자가 따로 요청한 뒤에만 진행합니다.

| 단계 | 내용 | 시작 조건 |
|---|---|---|
| GitHub 저장 | 비공개 저장소에 코드와 문서를 올림. `.env.local`은 제외 | 사용자가 저장소 주소를 알려 주고 "이 저장소에 올려 줘"라고 요청할 때 |
| Vercel 배포 | 저장소를 Vercel에 연결하고 환경 변수 `GEMINI_API_KEY`를 Vercel 화면에서 따로 입력한 뒤 배포. STEP 11에서 사용자가 직접 진행 | GitHub 저장과 별개로 사용자가 배포할 프로젝트·저장소를 정해 요청할 때 |
| 자동 배포 설정 | GitHub 변경이 곧바로 배포되게 하는 연결 | 사용자가 요청하기 전에는 추가하거나 켜지 않음 |

"구현 완료", "확인했어요", "알아서 해 주세요"만으로는 저장·배포를 시작하지 않습니다.
